# 2026-03-22 工作日志

## 热点追踪系统 V15 改进（HuggingFace 修复 + 写作包质量提升）

### 用户反馈
1. HuggingFace 数据源一直爬取不到
2. 腾讯云结合点、官方号写作角度、配图建议"AI 味很重"，没有基于不同热点做深度思考，所有项目都推 Lighthouse

### 根因分析

#### HuggingFace 爬取失败
- `fetch_huggingface_papers()` 通过 subprocess 调用 `fetch_hf_papers_playwright.py` 脚本
- **该脚本文件从未被创建**，所有 19 次历史运行 huggingface.json 全是空数组 `[]`
- 错误被内部吞掉（静默返回空列表），上层不知道失败了

#### 写作包质量问题
1. **Lighthouse 关键词太宽泛**：`agent`、`bot`、`open source`、`github.com` 几乎命中所有 GitHub 项目
2. **结合说明是套路模板**：所有项目都是"可以部署到 Lighthouse 上"
3. **配图建议模板化**：全是"产品截图/Logo + Lighthouse 服务器概念图"
4. **优先级判断宽松**：所有开发者话题都是 P0/P1

### 改动

#### 1. `fetch_news.py` — HuggingFace 爬虫重写
- 废弃缺失的 Playwright 脚本，改用 HuggingFace 官方 JSON API：`https://huggingface.co/api/daily_papers`
- 纯 requests 实现，无外部依赖
- 按 upvotes 降序排列，获取最热门论文
- 提取 title、url、github、upvotes、summary、authors、ai_keywords

#### 2. `content_analyzer.py` — 收紧 Lighthouse 关键词
- 移除：`agent`、`bot`、`assistant`、`automation`、`open source`、`open-source`、`github.com`、`deploy`、`deployment`、`docker`、`one-click`、`one click`
- 保留：明确的自部署信号（`self-hosted`、`docker compose`、`dockerfile`）和完整 Bot 短语（`discord bot`、`telegram bot` 等）

#### 3. `content_analyzer.py` — 收紧 CodeBuddy 关键词
- 移除：`code agent`、`ide`、`developer workflow`、`pull request`、`mcp`、`software development`
- 新增：明确竞品名 `windsurf`、`claude code`、`github copilot`、`tabnine`、`codeium`、`supermaven`
- 新增 explicit 匹配：`claude code`、`cursor ai`

#### 4. `content_analyzer.py` — 重写 `_compose_tcloud_storyline()`
- 结合说明现在包含具体的产品参数/能力描述（如 "3,200+ 节点"、"NVIDIA A100/H100"、"BM25 + 向量搜索"）
- 基于 detail_brief 内容做深度匹配，不再套固定模板
- 弱关联直接返回"关联较弱，建议人工判断"

#### 5. `content_analyzer.py` — 重写 `_build_visual_brief()`
- 配图建议现在基于 source_key（来源类型）而非产品类型
- GitHub 项目 → 用 README 截图/Demo GIF
- HN 文章 → 用核心观点金句图
- HuggingFace 论文 → 用论文核心图表
- ProductHunt → 用产品首图

#### 6. `content_analyzer.py` — 重写 `_build_angle_detail()`
- 不再只列标签（"产品关联（Lighthouse）"），而是基于结合说明给出具体写作方向
- 格式从 "A + B + C" 改为 "A → 可写方向：具体内容"

#### 7. `content_analyzer.py` — 重写官方号写作角度
- 基于热点具体内容 + 产品特性给出差异化写作建议
- 不再千篇一律"写一篇XX教程"

#### 8. `content_analyzer.py` — 修改优先级判断
- 不再所有开发者话题都是 P0/P1
- 需要 composite_score >= 8.0 才能 P0，>= 6.0 且是开发者话题才 P1

## 纯静态部署方案（GitHub Pages 免费）

### 架构
- 新增 `generate_static.py`：将 output/ 中的 CSV/Markdown 转为 docs/data/ 下的 JSON 文件
- 新增 `index.html`（纯静态前端）：从 data/*.json 加载数据，无需任何后端
- `docs/` 目录是 GitHub Pages 部署目录，包含 index.html + data/*.json
- 整个站点只有 ~300KB，纯静态零成本

### 部署流程
1. 本地运行 `./run.sh` 或手动 `python3 generate_static.py`
2. `git push` 到 GitHub
3. GitHub Actions 自动部署到 GitHub Pages（配置在 `.github/workflows/deploy.yml`）

### 前端功能（纯静态版）
- 数据看板 / 全量数据表（搜索+筛选+分页）/ 精选话题 / 每日总结 / 写作包 / 关于
- 支持多日期切换、关键词搜索、详情弹窗
- 深色主题、响应式设计

### 与原版 Flask 版本的区别
- `web_app.py` + `web_ui.html` = 本地使用（有一键采集、同步按钮）
- `index.html` + `docs/` = 部署版本（只读展示，适合分享和作品集）
- 两者可以并存

### GitHub Actions 自动化
- `deploy.yml`：推送 docs/ 时自动部署到 GitHub Pages
- `daily-collect.yml`：每天北京时间 9:00 (UTC 01:00) 自动采集 + 生成静态数据 + 部署
  - 也支持手动触发（workflow_dispatch）
  - 采集失败不阻断部署（continue-on-error）
- 仓库地址：`https://github.com/yuluu02/hotspot-tracker-for-tencentcloud`
- Pages 地址：`https://yuluu02.github.io/hotspot-tracker-for-tencentcloud/`
